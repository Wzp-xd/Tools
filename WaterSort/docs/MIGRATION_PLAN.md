# 水排序游戏 — GearSort 功能移植规划

> 将 `demo/GearSort` 的主界面、胜利弹窗、签到、道具系统移植到当前水排序项目。

---

| 维度 | GearSort（已完成） | 水排序（当前） |
|------|-------------------|---------------|
| 主界面 | 三 Tab（首页/任务/背包）+ Logo 动画 + 关卡选择 | 无，直接进入关卡 1 |
| 游戏 HUD | 金币、撤回/提示按钮、暂停、关卡标签 | 简易 topBar（关卡、撤回、重置） |

| 失败弹窗 | 广告续命 / 花金币保连胜 | 无 |
| 存档系统 | clientCloud 云存档（解锁进度/金币/连胜/道具/任务） | 无 |

## 五、实施步骤（建议顺序）

### 第一阶段：基础设施搭建

1. **SaveManager.lua** — 照搬 GearSort 存档结构，字段适配水排序：
   - 复用：`coins`, `winStreak`, `lastCheckInDay`, `undoCount`, `tempHubCount`, `taskClearedTotal`, `taskUndoClaimed`, `taskHubClaimed`
   - 适配：`unlocked`（关卡解锁数）、`levels`（每关最佳步数）
   - 接入 `clientCloud:Get/Set` 异步加载

2. **UIAnim.lua** — 移植 GearSort 的 Tween 引擎：
   - `UIAnim.Tween({ target, from, to, duration, easing, onUpdate, onComplete })`
   - `UIAnim.PopupIn(panel)` / `UIAnim.PopupOut(panel, cb)`
   - `UIAnim.CancelAll(target)`
   - 缓动函数集（easeOutCubic, easeOutBack, easeOutElastic, easeOutBounce, easeInOutSine）
   - 每帧在 `HandleUpdate` 中调用 `UIAnim.Update(dt)`

3. **FlyEffect.lua** — 移植飞金币 + 飞道具粒子：
   - 贝塞尔弧线飞行（支持散布、错开延迟）
   - 通用接口：`FlyEffect.PlayCoins(srcX, srcY, dstX, dstY, count, onDone)`
   - 通用接口：`FlyEffect.PlayItem(iconPath, srcX, srcY, dstX, dstY, onDone)`

### 第二阶段：主界面

4. **main.lua 改造** — 增加 `phase_` 状态机：
   - `"menu"` → 显示 MainMenu，隐藏游戏画面
   - `"game"` → 显示 UIOverlay + GameCanvas，隐藏菜单
   - 切换时播放过渡动画

5. **MainMenu.lua** — 按 GearSort `main_menu.lua` 结构构建：
   - 顶栏：金币数量（带图标）
   - 底部导航：首页 / 任务 / 背包 三个 Tab
   - 首页：Logo + 开始游戏按钮 + 关卡选择 + 连胜进度条 + 签到入口
   - 任务：通关任务卡片（每 5 关奖撤回、每 10 关奖临时管）
   - 背包：道具库存展示

6. **关卡选择面板** — 网格布局（5×8 或滚动列表）：
   - 显示：已通关（星级）、已解锁（可点击）、未解锁（锁定灰色）
   - 点击已解锁关卡 → 进入游戏

### 第三阶段：游戏内 UI 升级

7. **UIOverlay.lua** — 替换当前简易 topBar：
   - HUD：左侧暂停按钮、中间关卡标题、右侧金币 + 道具按钮
   - 道具按钮带数量角标，点击消耗道具

8. **胜利弹窗**：
   - 触发条件：`game.isWin == true` 且所有动画完成
   - 内容：星级评分（≤最优步数=3星，+3步=2星，其余1星）、金币奖励、连胜倍率
   - 演出流程：弹窗 PopupIn → 飞金币 → 按钮出现（下一关 / 返回主界面）
   - 数据更新：SaveManager 记录最佳步数、累加金币、更新连胜

9. **失败弹窗**（可选，水排序无步数限制时可延后）：
   - 触发：玩家主动放弃 or 无解检测
   - 选项：看广告续命 / 花金币保连胜 / 重试 / 返回

10. **暂停弹窗**：
    - 继续游戏 / 重新开始 / 关卡选择 / 返回主界面

### 第四阶段：签到 & 道具

11. **CheckIn.lua** — 每日签到：
    - 判断 `lastCheckInDay` 是否为今天
    - 签到奖励表（第 1-7 天循环，金币递增 or 道具）
    - 签到后飞金币/飞道具动画 → 更新 SaveManager → 刷新 UI

12. **道具系统接入**：
    - **撤回道具**：HUD 撤回按钮改为消耗道具（0 个时置灰或提示获取途径）
    - **临时管道具**：HUD 增加"+ 管"按钮，消耗后动态添加临时管到 GameState

13. **AdDialog.lua** — 通用广告弹窗：
    - 两种模式：纯广告 / 广告+花金币二选一
    - 接入 `sdk:ShowRewardVideoAd`

### 第五阶段：经济 & 打磨

14. **config.lua 扩展** — 新增经济配置：
    ```lua
    config.economy = {
        baseReward = 10,              -- 通关基础金币
        streakMultipliers = {1, 2, 5, 10, 15},  -- 连胜倍率
        checkInRewards = {20, 30, 40, 50, 60, 80, 100},  -- 7天签到奖励
        undoCost = 0,                 -- 撤回道具花费金币（0=仅消耗道具）
        tempHubCost = 0,              -- 临时管花费金币
        keepStreakCost = 50,          -- 保连胜花费金币
    }
    ```

15. **连胜系统**：
    - 通关 +1 streak，失败清零
    - 连胜条 UI（5 节点进度条，对应 5 个倍率档位）
    - 失败时可花金币保连胜

16. **UI 美化打磨**：
    - 配色主题统一（深色系 navy + 蓝色强调色）
    - 按钮/卡片带背景图或渐变
    - 弹窗动画精调（弹性/回弹参数）

## 六、关键适配点（GearSort → 水排序差异）

| 维度 | GearSort 原逻辑 | 水排序适配 |
|------|-----------------|-----------|
| 操作对象 | 齿轮（Gear） | 水层（Layer） |
| 柱/管 | Peg（柱子） | Tube（试管） |
| 移动动画 | 单齿轮贝塞尔弧线 | 试管倾倒 4 阶段动画（已实现） |
| 提示系统 | Solver 贪心算法 | 需适配水排序规则（连续同色一次倒完） |
| 关卡容量 | 每柱 4 齿轮 | 每管 4 层（可配置） |
| 失败条件 | 步数限制 | 无步数限制（可选：无解检测） |
| "完成"判定 | 柱内全同色 | 管内全同色（已实现） |
| 临时容器 | Temp Peg（容量 1） | Temp Tube（容量可配置，已实现） |
| NanoVG 渲染 | 齿轮图片 pattern | 水面液体渲染（已实现） |
| UI 框架 | urhox-libs/UI | 相同，可直接复用 |

## 七、风险 & 注意事项

1. **main.lua 改造幅度大** — 当前 main.lua 兼顾游戏逻辑 + UI 构建 + 渲染，需拆分出 UIOverlay 模块
2. **GameCanvas Widget 保留** — 游戏核心渲染逻辑（自定义 Widget）保持不变，仅将其嵌入新的 UI 层级
3. **并发动画兼容** — 飞金币/弹窗动画与倒水动画并行时，确保 `HandleUpdate` 中所有动画系统都被驱动
4. **存档迁移** — 首次接入 SaveManager 时需兼容无存档情况（默认值兜底）
5. **道具经济平衡** — 撤回从"免费无限"变为"消耗道具"，可能影响体验；建议保留"每关免费 N 次"基础额度
6. **代码行数控制** — MainMenu + UIOverlay 可能各超 1000 行，提前按模块拆分（如 CheckIn 独立文件）
